# Discord Changelog Pipeline — Design Spec

**Date:** 2026-04-01
**Linear:** TEN-41
**Status:** Approved

---

## Overview

Two independent Claude Code `PostToolUse` hooks that automatically post messages to Discord channel `1488606233807028275` when:

1. A Linear issue is marked **Done**
2. A **`git push`** is executed

Both hooks call a single script (`scripts/discord_notify.py`) with a `--mode` flag. The script reads the hook JSON payload from stdin, decides whether to act, formats a message, and POSTs to Discord via the REST API.

---

## Architecture

```
PostToolUse: mcp__linear__save_issue  ──→  discord_notify.py --mode done
PostToolUse: Bash                     ──→  discord_notify.py --mode push
                                                │
                                      reads stdin (hook JSON payload)
                                      loads DISCORD_TOKEN from .env
                                                │
                              ┌─────────────────┴──────────────────┐
                           done mode                           push mode
                    checks state == "Done"             checks "git push" in cmd
                    reads description from             skips dry-run / branch delete
                    tool_response payload              runs git log origin..HEAD
                    calls Groq for one-liner           buckets commits by prefix
                                              │
                              POST /channels/1488606233807028275/messages
                              Authorization: Bot <DISCORD_TOKEN>
```

Hooks are configured in `.claude/settings.local.json` (project-level, not global).

## Message Formats

### Done mode

```
✅ **[TEN-41]** Pipeline: send Discord changelog on task completion
Added PostToolUse hooks for Linear Done and git push, auto-posting changelogs to Discord.
```

- Title comes from `tool_response.title`
- Identifier comes from `tool_response.id` (e.g. `TEN-41`)
- One-liner summary generated by Groq from `tool_response.description`
  - Prompt: summarise as a single changelog sentence (≤120 chars), past tense, starts with a verb
  - Fallback: first non-empty line of description, truncated to 120 chars

### Push mode

```
📦 **Changelog** · `dev`

**Added**
- implement RAG pipeline scraper and indexer

**Updated**
- clarify index management commands in README
- add bot restart policy after output-affecting changes

**Fixed**
- handle rate limit backoff on scraper
```

- Branch name extracted from the `git push` command or `git rev-parse --abbrev-ref HEAD`
- Commits from `git log origin/<branch>..<branch> --pretty=format:"%s"`
- Categorisation by conventional commit prefix:
  - `feat:` → **Added**
  - `fix:` → **Fixed**
  - `refactor:`, `docs:`, `chore:`, `perf:`, `test:`, `ci:` → **Updated**
  - Unparseable → **Updated** (fallback)
- Prefix stripped, first letter capitalised for bullet text
- Sections with no commits are omitted

## Implementation

### New file: `scripts/discord_notify.py`

- Entry point: reads `sys.argv` for `--mode done|push`
- Reads hook payload from `stdin` as JSON
- Loads `DISCORD_TOKEN` (and `GROQ_API_KEY` for done mode) from `.env` via `python-dotenv`
- `python-dotenv` is already an indirect dependency; add explicitly to `requirements.txt` if not present
- Uses `requests` (already in `requirements.txt`) for both Groq and Discord API calls
- Exits with code 0 in all cases (never crashes Claude's session)

## Error Handling

| Scenario | Behaviour |
|----------|-----------|
| `state != "Done"` in done mode | Exit 0, no message |
| Bash command not a `git push` | Exit 0, no message |
| `git push --dry-run` | Exit 0, no message |
| `git push origin :branch` (delete) | Exit 0, no message |
| No commits between `origin/branch` and `HEAD` | Exit 0, no message |
| Groq API fails | Fall back to first sentence of description |
| Discord POST fails | Log to stderr, exit 0 |
| `DISCORD_TOKEN` missing | Log warning to stderr, exit 0 |
| `GROQ_API_KEY` missing | Skip Groq call, use description fallback |
